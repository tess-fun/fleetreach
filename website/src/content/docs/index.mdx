Python, Go, Ruby and Java services, with CISA KEV and EPSS. Log4Shell leads because it is
being exploited and the repo is internet-facing, not because of its CVSS score alone.

package in several repos is one decision, ranked by how many repos it clears.

## What it does

<CardGrid>
  <Card title="Ranks fixes across the fleet" icon="list-format">
    Impact, blast radius, package rollups and a batched fix queue: one bump per package that
    clears every advisory it has, in every repo.
  </Card>
  <Card title="Prioritises by real risk" icon="warning">
    CISA KEV, FIRST EPSS and SSVC decisions from each repo's exposure and impact, so an
    internet-facing service outranks an internal tool.
  </Card>
  <Card title="Opens verified fixes" icon="approve-check">
    Lock-only bumps on branches, each re-scanned before it is pushed, as pull or merge
    requests on GitHub and GitLab.
  </Card>
  <Card title="Fails closed" icon="error">
    A repo it cannot read is an error, a partly read source is labelled, and exit code 2
    means "not complete". Never a false clean.
  </Card>
  <Card title="Tracks it over time" icon="random">
    History, SLAs per SSVC outcome or severity, time to fix, Slack and webhook
    notifications, issues per owner, and a static HTML report.
  </Card>
  <Card title="Produces the evidence" icon="document">
    CycloneDX and SPDX SBOMs, OpenVEX, SARIF for code scanning, and license policy
    reports, from the same files.
  </Card>
  <Card title="Proves reachability" icon="magnifier">
    Import-graph witness chains for npm and Python, and a sound call-graph analysis for
    Rust that can safely suppress what is never called.
  </Card>
  <Card title="Runs anywhere" icon="laptop">
    One static binary. Reads lockfiles, runs no package code, works offline and in
    air-gapped networks.
  </Card>
</CardGrid>

## In CI in five lines

```yaml
- uses: actions/checkout@v4
- uses: tess-fun/fleetreach@v1
  with:
    args: "--enrich --fail-on-kev"
```

Findings go to the GitHub Security tab as SARIF. For a whole org, schedule one job over a
`[[source]]`. See [GitHub Actions](/fleetreach/docs/integrations/github-actions/) and
[GitLab CI](/fleetreach/docs/integrations/gitlab-ci/).

## How it compares

| | Scope | Answers | Shape |
|---|---|---|---|
| **fleetreach** | every repo, one run | which fix clears the most repos, for whom, by when | one binary |
| osv-scanner, Trivy, Grype | one project or directory | is this project vulnerable? | one binary |
| Dependabot, Renovate | one repo at a time | which updates to open | hosted bot |
| Dependency-Track | a portfolio of SBOMs | what components are where | a server you run |

## For AI agents and LLMs

This site publishes [`llms.txt`](/fleetreach/llms.txt) and
[`llms-full.txt`](/fleetreach/llms-full.txt), and every page has a Markdown copy at
`index.md` beside it. fleetreach's JSON report and `--help` output are stable inputs for
agents that triage or fix dependencies.
