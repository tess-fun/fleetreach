## 211 findings, 38 fixes, 2 for today

A real run on the [demo fleet](/fleetreach/docs/getting-started/first-scan/): nine services
in Rust, npm, Python, Go, Ruby and Java. Per-repo scanners report 211 findings, 15 of them
critical. fleetreach turns them into 38 bumps, one per package, each clearing every advisory it has in every
repo, and SSVC marks 2 of them for today. Log4Shell leads because it is being exploited
and the repo is internet-facing, not because of its CVSS score.

## The whole job, not one step of it

Most tools cover one step and hand off to the next. fleetreach covers all of them from the
same files, so the finding you prioritise is the one you fix, suppress and report on.

<CardGrid>
  <Card title="Inventory" icon="list-format">
    Lockfiles in 12 ecosystems, container images on 20+ distributions, Go and Rust binaries,
    jars and gems inside images, SBOMs from other tools, and whole orgs on GitHub, GitLab,
    Gitea, Forgejo, Bitbucket and Azure DevOps.
  </Card>
  <Card title="Detect" icon="magnifier">
    OSV, RustSec, vendor feeds and CSAF VEX from Red Hat and SUSE, known malware, and
    supply-chain signals: install scripts, typosquats, fresh releases, abandoned packages.
  </Card>
  <Card title="Prioritise" icon="warning">
    CISA KEV, EPSS, public exploits and SSVC decisions from each repo's exposure. Import
    chains from your own code in eight ecosystems, and sound call graphs for Rust, Java and .NET that can set
    aside what is never called.
  </Card>
  <Card title="Fix" icon="approve-check">
    A batched fix queue, `whatif` to see what a bump clears before any edit, and fix pull
    requests on six forges, each re-scanned before it is pushed.
  </Card>
  <Card title="Decide" icon="pencil">
    Triage decisions kept as files in git, VEX read from OpenVEX, CycloneDX, CSAF and signed
    OCI attestations, and VEX written back that Trivy and Grype honour.
  </Card>
  <Card title="Prove" icon="document">
    CycloneDX and SPDX SBOMs with NTIA checks, license policy and NOTICE files, SARIF for
    code scanning, and a coverage record that names anything that was not read.
  </Card>
  <Card title="Operate" icon="random">
    History, SLAs that never reset, time to fix, drift between scans, Slack and webhook
    notifications, issues per owner, an HTML report and a local triage UI.
  </Card>
  <Card title="Run anywhere" icon="laptop">
    One static binary that reads files and runs no package code. Works offline and
    air-gapped from a hash-checked advisory bundle, and exits 2 when coverage is incomplete.
  </Card>
</CardGrid>

## In CI in five lines

```yaml
- uses: actions/checkout@v4
- uses: tess-fun/fleetreach@v1
  with:
    args: "--enrich --fail-on-kev"
```

Findings go to the GitHub Security tab as SARIF. For a whole org, schedule one job over a
`[[source]]`. See [GitHub Actions](/fleetreach/docs/integrations/github-actions/) and
[GitLab CI](/fleetreach/docs/integrations/gitlab-ci/).

## How it compares

| | Scope | Answers | Shape |
|---|---|---|---|
| **fleetreach** | every repo and image, one run | what to fix first, for whom, by when, and the proof it was done | one binary |
| osv-scanner, Trivy, Grype | one project, directory or image | is this vulnerable? | one binary |
| Dependabot, Renovate | one repo at a time | which updates to open | hosted bot |
| Dependency-Track | a portfolio of SBOMs | what components are where | a server you run |
